# Implementation Roadmap, Repository Structure and Copilot Protocol

## Objective
Translate the playbook into incremental implementation without large uncontrolled code generation.

## Required implementation sequence
Foundation, domain contracts, configuration/environment separation, audit/event model, market data, analysis modules, agent orchestration, strategy/signal engine, validation engine, risk engine, approval gateway, paper execution, exchange abstraction, live safeguards, frontend, learning layer, observability, production hardening.

## Repository structure
apps, services, packages, agents, data, infrastructure, tests, docs, scripts, configs, .github.

## Copilot discipline
Before changes: inspect repo, identify architecture, modules, dependencies, contradictions, missing requirements, existing interfaces, database conventions, event infrastructure, LangGraph state, risk controls, execution controls. Then propose a plan and wait for approval.

## Dangerous capabilities
Live trading disabled by default. Production exchange credentials never generated by Copilot. No automatic strategy promotion. No unreviewed critical financial code. No LLM-generated risk formulas without deterministic tests.
