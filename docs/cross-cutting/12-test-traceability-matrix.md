# Test Traceability Matrix

This registry defines the mandatory verification baseline for safety-critical implementation. It identifies tests that future implementation issues must deliver; it does **not** claim that executable runtime tests already exist or pass.

## Evidence rules

- Each implementation PR must reference its applicable `TST-###`, `RT-###`, and `TB-###` identifiers and link the resulting test files and CI evidence.
- Automated verification is mandatory where behavior is machine-verifiable. Manual review supplements automation; it never substitutes for deterministic safety tests.
- Tests must use synthetic fixtures, mocks, simulators, paper/shadow/testnet environments, or other non-live harnesses until live operation is separately approved.
- A test passes only when the prohibited outcome is prevented and the expected fail-closed result is observable and auditable.
- Missing, skipped, flaky, unverifiable, or environment-inappropriate safety evidence does not satisfy the baseline.
- No test may use real secrets, initiate an unapproved live order, move funds, or fabricate market/performance evidence.

## Manual verification boundary

Manual verification is required for authenticated human intent, usability/operational clarity, governance decisions, policy approval, audit sampling, and incident/recovery authorization. Manual sign-off cannot make a failing automated safety check pass and cannot authorize an untested bypass.

## Implementation evidence status

All rows above are **required future evidence**. Executable test paths and CI run links must be added by the implementation issue that first introduces the relevant behavior. Until then, the status is `BASELINE_DEFINED / EXECUTABLE_EVIDENCE_PENDING`, not “passed.”
