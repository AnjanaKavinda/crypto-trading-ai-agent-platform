# Definition of Done

A task is done only when:
- issue acceptance criteria are satisfied;
- applicable playbook requirements and contracts are followed;
- tests are added/updated and pass;
- no unrelated changes are bundled;
- no secrets are introduced;
- security/safety impact is reviewed;
- documentation and ADRs are updated where required;
- contract/version implications are documented;
- failure behavior is defined for critical paths;
- observability/audit requirements are addressed;
- deferred work is explicit;
- QA blockers are resolved or explicitly rejected by the human owner;
- the human owner approves merge.

Generated code alone is never Definition of Done.
